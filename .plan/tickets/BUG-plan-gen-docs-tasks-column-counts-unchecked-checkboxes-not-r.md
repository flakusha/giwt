# BUG: plan gen-docs Tasks column counts unchecked checkboxes, not Related tickets list entries

**Status:** Done
**Priority:** low
**Effort:** Small
**Tags:** gen-docs, plan, documentation

**Summary:**

Repro (loop-lore repo, generated by this gen-docs):

- /home/flak/git-ai/loop-lore/.plan/epics/epic-model-metadata-read.md lists 7 entries under '## Related tickets', but .plan/epics-index.md shows Tasks = 4.
- Same pattern: epic-local-model-file-discovery.md has 3 related tickets vs index Tasks = 4; epic-model-info-frontend.md has 2 vs 3.

Root cause (characterized by reading the generator):

src/plan/gen-docs.ts parseEpic() (lines ~49-50) computes taskCount via raw.match(/- \[ \]/g) — it counts ALL unchecked '- [ ]' checkboxes anywhere in the epic file, which in practice are the '## Acceptance Criteria' items, not the '## Related tickets' list. Verified: epic-model-metadata-read.md contains exactly 4 unchecked checkboxes (its acceptance criteria) and 0 checked ones; 4 matches the index cell. epic-llama-swap.md: 5 unchecked → index 5. The column is therefore not wrong per its implementation, but its 'Tasks' label does not mean the number of related tickets, so readers comparing it to the Related tickets list see a mismatch.

Suggested fix direction (cosmetic/semantic, nit — no data loss):

Either (a) rename the column to something accurate like 'Open criteria' / 'Unchecked', or (b) actually count '## Related tickets' list entries under that section if ticket-count semantics are wanted, or (c) document the meaning in the index header/legend. Pick one; (b) changes semantics and may need an epic-frontmatter convention first.

**Context:**

Fixed in commit `f3d6e03`, then corrected after review: `parseEpic()` in `src/plan/gen-docs.ts` now scopes the Tasks column to the task-bearing sections only — done/total over `## Linked Tasks` checkboxes plus `## Related tickets` entries (checkbox-style related entries count once; checkbox prose elsewhere, e.g. acceptance criteria, is excluded). The first cut summed file-wide checkboxes with related entries, double-counting checked entries under `## Related tickets` (done could exceed total) and conflating acceptance criteria with tasks.

Resolution: fix landed as `0e20d9f` (Tasks column counts Related-tickets list entries; AC checkboxes excluded).
